# Docker — قالب موحّد لتهيئة بيئة تشغيل التطبيقات + عرض حي

حزمة جاهزة للعرض: تطبيق تجريبي صغير، و**Dockerfile موحّد** يكون قالبًا لكل الفرق، وقوالب للغات الشائعة، وسكربت عرض حي خطوة بخطوة.

> التطبيق التجريبي لا يحتوي أي بيانات حقيقية ولا يتصل بالإنترنت — آمن للعرض على أي منصة.

## محتويات المجلد

```
├── Dockerfile              ← القالب الموحّد (مثال Node.js) — مشروح سطرًا بسطر
├── .dockerignore           ← ما لا يدخل الصورة أبدًا
├── docker-compose.yml      ← بيئة كاملة بأمر واحد: proxy + 3 نسخ من التطبيق + Redis
├── src/                    ← كود التطبيق التجريبي (بدون أي مكتبات خارجية)
├── proxy/nginx.conf        ← موزّع الأحمال
├── templates/              ← قوالب Python و .NET و Java والواجهات + القواعد العشر
├── demo/run-demo.sh        ← سكربت العرض الحي (13 خطوة، ENTER لكل خطوة)
├── .devcontainer/          ← تشغيل فوري على GitHub Codespaces
└── render.yaml             ← نشر مجاني برابط عام على Render
```

## التشغيل على أي جهاز عليه Docker

```bash
docker compose up -d          # تشغيل البيئة كاملة
# افتح http://localhost:8080
./demo/run-demo.sh            # أو شغّل سيناريو العرض كاملًا خطوة بخطوة
docker compose down -v        # إيقاف وتنظيف
```

## التشغيل المجاني على الإنترنت

| المنصة | الاستخدام | مجانًا | ملاحظات |
|---|---|---|---|
| **GitHub Codespaces** (موصى به) | العرض الحي بالأوامر | 120 ساعة حوسبة شهريًا للحسابات الشخصية | Docker جاهز، أكثر استقرارًا |
| **Render** | رابط عام دائم للتطبيق | 750 ساعة شهريًا | ينام بعد 15 دقيقة بلا زيارات، ويحتاج نحو دقيقة ليستيقظ |
| **Play with Docker** | بديل سريع دون GitHub | مجاني بحساب Docker Hub | جلسة مؤقتة (ساعتان تقريبًا) وتُحذف بعدها |

### 1) GitHub Codespaces — للعرض الحي

1. أنشئ Repository جديدًا على GitHub (يمكن أن يكون Private) وارفع محتويات هذا المجلد.
2. من الـ Repository: **Code ← Codespaces ← Create codespace on main**، وانتظر دقيقتين.
3. في الـ Terminal: `./demo/run-demo.sh`
4. افتح تبويب **Ports** ← المنفذ `8080` ← أيقونة الكرة الأرضية لفتح التطبيق.
   لعرضه للحضور على أجهزتهم: كليك يمين ← **Port Visibility ← Public**.
5. بعد العرض: أوقف الـ Codespace حتى لا تُستهلك الساعات المجانية.

### 2) Render — رابط دائم تضعه في العرض

1. ادخل render.com وسجّل بحساب GitHub.
2. **New ← Blueprint** ← اختر الـ Repository ← **Apply** (يقرأ `render.yaml` تلقائيًا).
3. بعد اكتمال البناء يظهر رابط مثل `https://docker-demo-xxxx.onrender.com`.
4. **افتح الرابط قبل العرض بخمس دقائق** ليستيقظ التطبيق.

> على Render تعمل نسخة واحدة من التطبيق (بدون compose)، فالعدّاد داخل الحاوية وزر "محاكاة عطل" يعيد تشغيلها تلقائيًا.

### 3) Play with Docker — بديل سريع

1. ادخل labs.play-with-docker.com وسجّل بحساب Docker Hub مجاني ← **Start** ← **Add new instance**.
2. `git clone <رابط الـ Repository> demo && cd demo && docker compose up -d`
3. اضغط على الرقم **8080** أعلى الشاشة (أو **Open Port** واكتب 8080).
4. اللصق في الـ Terminal: `Ctrl+Shift+V` أو `Shift+Insert`.

## سيناريو العرض (≈ 10 دقائق)

| # | ما تفعله | ما يراه الحضور |
|---|---|---|
| 1 | `docker build` من القالب | صورة جاهزة في ثوانٍ |
| 2 | `docker run` حاوية واحدة | التطبيق يعمل + `id` يثبت أنه ليس root |
| 3 | `docker compose up -d` | بيئة كاملة (5 حاويات) بأمر واحد |
| 4 | تحديث الصفحة | حاويات مختلفة ترد بالتناوب |
| 5 | `--scale app=5` | 5 نسخ خلال ثوانٍ |
| 6 | زر "محاكاة عطل" | الحاوية تعود تلقائيًا خلال ثانية |
| 7 | `APP_VERSION=2.0.0` | الإصدار 2 (لون أخضر) والبيانات محفوظة |
| 8 | `APP_VERSION=1.0.0` | الرجوع للإصدار السابق فورًا |

## ملاحظات مهمة

- **الترخيص:** Docker Engine على Linux مجاني (Apache 2.0). أما Docker Desktop على Windows/Mac فيتطلب اشتراكًا مدفوعًا للجهات الحكومية — البديل المجاني: Podman Desktop أو Rancher Desktop أو تشغيل العرض على Codespaces.
- **الأمان:** لا يُرفع أي كود أو بيانات خاصة بالجهة على المنصات العامة — هذا التطبيق تجريبي فقط.
- **قوالب .NET و Java** تم فحص صياغتها فقط، وتُختبر على أول تطبيق فعلي.
